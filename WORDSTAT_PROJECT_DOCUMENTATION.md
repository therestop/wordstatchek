# Проект проверки ключевых фраз через Yandex Wordstat API

## 1. Назначение проекта

Проект создан для массовой проверки ключевых фраз через официальный Yandex Wordstat API.

Изначальная практическая задача:

> Сбор коммерческих ключевых фраз по теме ремонта плоских горизонтальных крыш на гаражах битумными рулонными наплавляемыми материалами.

Основные требования к результату:

- только коммерческие запросы;
- без регионов, если это отдельно не требуется;
- исключение информационных запросов;
- проверка каждой фразы через Wordstat;
- удаление фраз с нулевой частотностью;
- сохранение частотности рядом с каждой фразой;
- экспорт результата в TXT и CSV;
- возможность продолжить проверку после остановки;
- обработка ограничений и временных ошибок API.

## 2. Что было реализовано

В процессе разработки было создано несколько версий проверяющего скрипта.

### V1

Первая версия использовала старый Wordstat API:

```text
https://api.wordstat.yandex.net/v1/dynamics
```

Авторизация выполнялась через OAuth Bearer-токен.

Основная идея:

1. Читать фразы из TXT.
2. Проверять каждую фразу через API.
3. Суммировать частотность.
4. Сохранять ненулевые, нулевые и полный результат.

Позже выяснилось, что старая точка API больше не подходит для актуальной схемы работы.

## 3. Проблемы старого API

При использовании старого API возникли ошибки:

```text
SSLCertVerificationError
Hostname mismatch
```

и затем:

```text
HTTP 404 Not Found
```

Даже официальный метод `/v1/getRegionsTree` возвращал 404. После проверки было принято решение перейти на актуальную интеграцию Wordstat через Yandex Cloud Search API.

## 4. Актуальная архитектура Wordstat API

Рабочая версия проекта использует Yandex Cloud Search API v2.

Endpoint:

```text
POST https://searchapi.api.cloud.yandex.net/v2/wordstat/topRequests
```

Авторизация:

```http
Authorization: Api-Key <YANDEX_SEARCH_API_KEY>
```

Также требуется `folderId` каталога Yandex Cloud.

## 5. Настройка Yandex Cloud

Для работы необходимо создать сервисный аккаунт в Yandex Cloud.

Минимальная роль:

```text
search-api.webSearch.user
```

API-ключ должен иметь scope:

```text
yc.search-api.execute
```

Используются две переменные окружения:

```text
YANDEX_SEARCH_API_KEY
YANDEX_FOLDER_ID
```

Пример для PowerShell:

```powershell
$env:YANDEX_SEARCH_API_KEY="ВАШ_API_КЛЮЧ"
$env:YANDEX_FOLDER_ID="ВАШ_FOLDER_ID"
```

Запуск:

```powershell
python .\wordstat_check_v3.py
```

или:

```powershell
.\run_wordstat_v3.bat
```

## 6. Основной рабочий скрипт

Актуальная версия:

```text
wordstat_check_v3.py
```

Она работает через `/v2/wordstat/topRequests`.

Для каждой фразы в API передаётся примерно такой JSON:

```json
{
  "phrase": "ремонт крыши гаража",
  "numPhrases": 1,
  "folderId": "b1g..."
}
```

Из ответа используется `totalCount` — количество запросов за последние 30 дней.

## 7. Входной файл

По умолчанию используется TXT:

```text
kommercheskie_frazy_remont_kryshi_garazha.txt
```

Формат:

```text
ремонт крыши гаража
ремонт кровли гаража
перекрыть крышу гаража
```

Одна фраза на строку.

Перед проверкой выполняется:

- удаление пустых строк;
- удаление точных дублей;
- сохранение исходного порядка.

## 8. Логика проверки

```text
TXT
 ↓
загрузка фраз
 ↓
удаление точных дублей
 ↓
проверка checkpoint
 ↓
Wordstat API
 ↓
totalCount
 ↓
0 / > 0
 ↓
сохранение результата
 ↓
следующая фраза
```

Для каждой фразы:

```python
if totalCount > 0:
    status = "nonzero"
else:
    status = "zero"
```

## 9. Checkpoint

Одна из ключевых функций проекта — автоматическое продолжение проверки.

Файл:

```text
wordstat_v3_checkpoint.json
```

После каждой проверенной фразы результат записывается в checkpoint. Это позволяет закрыть окно, нажать Ctrl+C, перезагрузить компьютер или получить временную ошибку API, а затем продолжить с того же места.

Уже проверенные строки повторно в API не отправляются.

## 10. Обработка ошибок API

### HTTP 429

Означает превышение квоты:

```text
HTTP 429 Too Many Requests
```

Скрипт ждёт и повторяет запрос.

### HTTP 500 / 502 / 503 / 504

Временные проблемы сервиса. Используется повторный запрос с увеличивающейся паузой.

### HTTP 401 / 403

Обычно означает проблему с:

- API-ключом;
- scope;
- ролью сервисного аккаунта;
- Folder ID.

Для Wordstat потребовалось:

```text
search-api.webSearch.user
```

и:

```text
yc.search-api.execute
```

## 11. Квоты Wordstat

Во время первого большого прогона была достигнута квота около 100 запросов в час, после чего API начал возвращать HTTP 429. Квота была увеличена через поддержку Yandex Cloud.

Для промышленного использования веб-сервиса квоту нужно учитывать обязательно.

## 12. Выходные файлы

Скрипт V3 создаёт:

- `wordstat_v3_nonzero.txt` — только ненулевые фразы;
- `wordstat_v3_nonzero.csv` — ненулевые фразы + частотность;
- `wordstat_v3_zero.txt` — нулевые;
- `wordstat_v3_errors.txt` — ошибки;
- `wordstat_v3_all.csv` — полный результат;

## 13. Реальные результаты проекта

В процессе работы были получены следующие результаты:

- первый набор: 231 фраза;
- расширенный пул: 8 402 уникальных кандидата;
- Wordstat подтвердил 959 ненулевых;
- после семантической очистки: 865 целевых коммерческих, 60 пограничных, 34 мусорных;
- после жёсткой фильтрации «только гаражи»: 712 фраз;
- затем был сформирован новый пул без точных пересечений с прежними 8 402;
- частичный новый прогон дал ещё 227 ненулевых;
- после объединения получилось 939 уникальных ненулевых фраз.

## 19. Будущий веб-сервис

На основе рабочего скрипта планируется веб-сервис.

Основная идея:

1. Пользователь регистрируется.
2. Загружает TXT.
3. Одна строка = одна ключевая фраза.
4. Выбирает параметры.
5. Система считает количество фраз.
6. Показывает стоимость.
7. Пользователь запускает проверку.
8. Задание отправляется в очередь.
9. Worker проверяет Wordstat.
10. Пользователь видит прогресс.
11. После завершения скачивает TXT и CSV.

## 22. Почему нужен worker

Нельзя проверять десятки тысяч фраз прямо внутри обычного HTTP-запроса.

Правильная схема:

```text
Пользователь
   ↓
создать задачу
   ↓
Backend
   ↓
Redis Queue
   ↓
Wordstat Worker
   ↓
Yandex API
```

Пользователь может закрыть вкладку, а задача продолжит выполняться.

## 30. Безопасность

API-ключ Yandex Cloud:

- не хранить во frontend;
- не писать в Git;
- не писать в логи;
- не хранить открытым текстом в БД.

Рекомендуется использовать `.env`, Secret Manager, Yandex Lockbox или другой защищённый secret storage.
